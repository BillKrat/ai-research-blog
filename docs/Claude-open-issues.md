## OI-1: mcp.global-webnet.com has no working TLS (found 2026-10-18)

- **Symptom:** the WebApi health check logs `The SSL connection could not be established` calling `https://mcp.global-webnet.com/api/hello`; the Standard-Retry resilience handler retries 3 times (about 8-10 s per `/api/health`), then reports "Failed to reach mcp".
- **Evidence:** every run since 2026-10-11 (125 failures in the 10-11 log, 15 on 10-15, repeating on 10-18 across minutes, so not a cold start). `curl` from the same machine gets `Connection was reset` during the handshake for `mcp.` while `api.` and `www.` return 200 with a valid certificate. Plain http to mcp answers 404, so the site is up; only its HTTPS binding is missing.
- **Cause (likely):** the 2026-10-11 free-SSL migration covered the bare domain, `www` and `api`, but not `mcp`.
- **Confirmed 2026-10-18:** SmarterASP `domains_list` shows `mcp.global-webnet.com` with `sslStatus: not_configured`. `ssl_request` was refused with `ssl_preflight_failed`: the domain must answer HTTP 200 on its root without redirecting, and the MCP site's `/` returned 404 (and every path was redirected to https).
- **Fix, in two steps:** (1) done on branch `claude-users-roles`: McpServer answers 200 on `/` and no longer redirects it (as the API already does); it takes effect when the branch is merged to `main` and deployed. (2) After that deploy, call `ssl_request` for `site-1885461` / `mcp.global-webnet.com` (or request it in the panel), then re-run `curl https://mcp.global-webnet.com/api/hello`.
- **Status 2026-10-18 (later):** step (1) is merged to `main` and deployed (http root answers 200). Step (2) is blocked on the vendor: `ssl_request` now passes the preflight but SmarterASP answers `ssl_request_failed` / "did not queue the SSL request" (operation `7de35838-9ca4-4d83-9ec1-9d8412dca6ae`, retryable; a second attempt with a fresh key failed the same way). Next: retry later; if it persists, request the certificate in the SmarterASP panel or open a support ticket. Until then the mcp deploy workflow's HTTPS smoke test fails (the deploy itself completes) and the API's health check reports mcp unreachable.
- **Panel review 2026-10-19 (Chrome, read-only):** the SmarterASP panel's SSL page lists 3 installed certificates (api, global-webnet.com, www with the paid Sectigo one) and none for `mcp`. The mcp site's own SSL dialog shows 0 installed / 0 pending and offers only CSR Request, Buy SSL and Import SSL: no free option, which is why `ssl_request` cannot queue it. Cause: `mcp.global-webnet.com` is a custom domain mapped onto the standalone site `mcp` (site5), whereas `api` was created with "+ Sub Domain" (a SUBSITE of the owned domain `global-webnet.com`), and that kind gets the free certificate. Options: (a) create `mcp` as a subsite of `global-webnet.com` via "+ Sub Domain", remove the domain mapping from site5, point the deploy workflow's FTP target and secrets at the new site, redeploy, then `ssl_request` (free); (b) buy a certificate for the mapped domain (paid, outside the budget); (c) leave mcp without TLS (not acceptable for token-carrying calls). Nothing was bought or changed.
- **Ticket:** SmarterASP #3715425 (2026-10-19) asks them to issue the free certificate for the mapped subsite. The subsite migration steps 1-5 are done (`mcp` = `site-1896089`, serving over HTTP); only the certificate is outstanding.
- **Plan:** [Claude-decision-2026-10-mcp-subsite-migration.md](Claude-decision-2026-10-mcp-subsite-migration.md) (panel steps await the human's confirmation one by one).
