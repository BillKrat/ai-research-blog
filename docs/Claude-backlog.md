- **Diagnose button (from the human, 2026-10-18): first version built 2026-10-19 (see the stage review); keep adding a rule per exception we meet; later an optional AI call (needs an API key and a data decision).** Original idea: when the diagnostics are mature, a Diagnose action on an exception or signature that runs a triage process and reports a verdict: gather the request's log lines and exceptions by CorrelationId (`IDiagnosticsReader`), check the dependencies involved (health probe, TLS, database), compare with earlier occurrences of the same signature, and propose a cause and next step. Starts as the read-only checklist a human or Claude follows; automate each step as it proves reliable.
- **Admin dashboard.** Status actions DONE (2026-10-20: Acknowledged / Fixed per kind, Regressed set by the system). Still open: move the exceptions area onto a Dashboard with signatures counted per day and links from a signature to its occurrences.
- **Performance thresholds and alerts (from the human, 2026-10-20).** Let an administrator set thresholds for performance (for example the p95 duration of an API endpoint, a database or N-Quad store query, an outbound call such as mcp or Anthropic, or a store round-trip count per request); when one is exceeded a warning icon shows (the same header icon family as exceptions) and we are alerted. Each alert then has two outcomes: raise the threshold (an informed decision, recorded) or look for an improvement. Particularly important because entities live in the N-Quad store, where one logical read is several quad queries and cost grows with data. Ideas to start from: time every request and store call with the CorrelationId already carried (the timings the health check and "responded in N ms" log lines already have); keep rolling percentiles per endpoint and per store operation; thresholds as configuration the admin edits on the Dashboard; a breach is recorded like an exception (throttled, with a signature and Acknowledged/Fixed status) so Diagnose and the MCP tool see it; count store calls per request to catch N+1 early (`NQuadEntityRepositoryListCostTests` pins this for one path). Needs a decision on storage of the measurements (in memory vs the store) and on how we are alerted (icon only, or e-mail/push).
